# คู่มือเขียนข่าว /news/ (DOJOJIN.TECH)

อัปเดต 2026-11-12 ตามที่เจ้าของเว็บอนุมัติ — ใช้ทุกครั้งที่เขียนหรือแก้ข่าว (คน, Claude, sonnet subagent, cron)

## ขั้นตอน
1. สรุปข่าว (cron 08:20/16:20 → `~/news-digest/`) → เจ้าของเลือกเลข → เขียน → เจ้าของตรวจ → commit/deploy เมื่อสั่งเท่านั้น
2. ยืนยันข้อเท็จจริงกับต้นทาง (ผู้ผลิต/รัฐ) ห้ามแต่งตัวเลข ราคา วันที่ ถ้าไม่รู้ข้อมูลไทยให้เขียนตรง ๆ
   - **ห้ามลงข่าวที่มีสื่อเจ้าเดียว** (เจ้าของสั่ง 14 พ.ย. 2569 หลังข่าว EV 4 เรื่องพึ่ง Autolife เกือบทั้งหมด "มันจะดูเป็นการก๊อปข่าวเค้ามาลง"): ต้องมีต้นทาง (ข่าวแจก/เว็บ/เพจทางการของแบรนด์หรือหน่วยงาน) หรือสื่ออื่นอย่างน้อย 2 เจ้าที่ยืนยันตรงกัน แล้วเรียบเรียงเองจากข้อมูลรวม · `sourceName` และย่อหน้าแรกห้ามเป็นสื่อเจ้าเดียว · อ้างแต่ละแหล่งครั้งเดียว · หาแหล่งที่สองไม่เจอ = ไม่ลง (ข่าว LEPAS L6, ORA 5 PLUS, SHARGE, Wuling MINI EV ถูกลบด้วยเหตุนี้)
3. ภาษา: ไทยง่าย ๆ เสียงเจ้าของ (ผม/ครับ) ไม่แปลทีละบรรทัด ไม่มี emoji
4. **Copywriter pass ทุกข่าว โดย agent Opus แยกอีกตัว** (เจ้าของสั่ง 13 พ.ย. 2569 หลังร่างของ Sonnet อ่านแข็งเหมือนแปลรายการแหล่งข่าว): Sonnet เขียนร่างเสร็จ → ส่ง agent Opus (model `opus`) เกลาสำนวนก่อนให้ main model ตรวจและก่อนส่งเจ้าของทุกครั้ง ห้ามข้าม
   - เกลาเป็นเสียงเจ้าของ **แบบเดียวกับที่เจ้าของเขียนรีวิว** (อ่าน `src/content/posts/review/` 2–3 เรื่องก่อนทุกครั้ง: ผม/ครับ เล่าตรงกับคนอ่าน บรรทัดสั้น มีความเห็นสั้น ๆ แบบ "ผมว่า…"): ประโยคสั้น ประเด็นก่อนรายละเอียด แตกย่อหน้าแน่น ๆ ตัวเลข/ชื่อหลายตัวทำเป็นลิสต์ อ้างสื่อครั้งเดียวต่อเรื่องให้อ่านลื่น ไม่ต้อง "(ตาม X)" ทุกวลี ศัพท์เฉพาะ/ชื่อย่อหุ้น (เช่น NVDA, FY, 8-K) อธิบายครั้งแรกหรือใช้คำไทยแทน ไม่ advertorial
   - ห้ามเปลี่ยนข้อเท็จจริง ตัวเลข วันที่ ชื่อ คำพูด ลิงก์ การอ้างที่มา โครงสร้าง HTML/split ภาพ alt เครดิต ส่วนแหล่งข้อมูล/ที่มาของภาพ
   - agent ต้องรัน build + lint + check-splits ผ่าน และรายงาน before → after

## ภาพ
- ห้ามใช้ภาพจากสำนักข่าวไทย/เว็บข่าวไทย · ภาพแบรนด์ทางการ ภาพหน้าจอ เว็บต่างประเทศใช้ได้พร้อมเครดิต
- ข่าวสินค้า: ปก = ภาพทางการของแบรนด์ · ไม่มีภาพทางการ: ภาพประกอบที่สร้างเอง
- **ห้ามเขียนว่า AI / Codex** ที่ไหนเลย (ข้อความ เครดิต alt หรือในภาพ) ใช้ "ภาพประกอบ" / "ภาพประกอบจาก DOJOJIN.TECH"
- **เครดิตภาพปก = "by dojojin.tech" เท่านั้น** (เจ้าของสั่ง 16 พ.ย. 2569) ไม่บอกว่าทำด้วยเครื่องมืออะไร ใช้กับทุกประเภทบทความ (ข่าว ความรู้ รีวิว)
- ห้ามใช้ภาพที่เป็นแค่โลโก้หรือมาสคอตที่ไม่สื่อเนื้อหา
- **ห้ามใช้ปกตัวหนังสือล้วนกับข่าวทั่วไป** (เจ้าของสั่ง 17 พ.ย. 2569 "ไม่เอาปกแบบนี้สำหรับข่าวทั่วไป ... มันไม่น่าสนใจ"): ปกต้องมีภาพจริงเป็นพื้น (ภาพทางการของแบรนด์ ภาพหน้าจอจริง หรือภาพประกอบฉากที่ทำเอง) + ชื่อเรื่องตัวใหญ่ซ้ายบน + ตัวเลข/ราคาสำคัญขวาบน + ชิป 2–3 อัน · ใช้ `scripts/content/photo_cover.py` + `render_cover.mjs` (ตัวอย่าง spec ใน `_sources/posts/news/*/cover-v2/`) · ภาพสินค้าพื้นขาวใช้ `"mode":"light"` · ชิปห้ามทับจุดเด่นของภาพ (ย้ายขวาด้วย `chips_right`) · `news_cover.py` (ปกตัวหนังสือ) ใช้ได้เฉพาะเมื่อไม่มีภาพเลยจริง ๆ และต้องถามเจ้าของก่อน
- **ข่าวที่เกี่ยวกับแบรนด์/สินค้าที่มีโลโก้ ต้องใส่โลโก้จริงบนปก** (เจ้าของสั่ง 17 พ.ย. 2569 "เอา logo Expedia มาใส่ด้วยครับ ถ้าเป็นเกี่ยวกับ products ที่มี logo จดเรื่องนี้ไว้หน่อย"): ใช้ไฟล์โลโก้ทางการ (หน้า press/IR/brand ของบริษัท เก็บใน `_sources/.../logo/`) ใส่ `"logo"` ใน spec ของ `photo_cover.py` (วางบนแผ่นขาวเหนือหัวเรื่อง) · เครดิต "โลโก้ <แบรนด์> จาก <เว็บ>" ในบรรทัดภาพปก · ข้อยกเว้น: ข่าวที่โลโก้จะทำให้ดูเหมือนแบรนด์เป็นผู้ร้าย ให้ถามก่อน
- **ตรวจภาพประกอบที่สร้างเองทุกภาพก่อนใช้:** มือ/นิ้ว/แขน (จำนวน ข้างซ้ายขวา) ใบหน้า ตัวหนังสือมั่ว — 17 พ.ย. 2569 ภาพปก Expedia มีมือขวาสองมือ เจ้าของจับได้ · ถ้าไม่จำเป็นต้องมีคน ให้สั่งฉากที่ไม่มีคน ("NO PEOPLE, no hands")
- **ภาพปก (cover) = 1600×1200 (4:3) เสมอ** (เจ้าของสั่ง 14 พ.ย. 2569 หลังปก Rectangle 2:1 โดนตัดข้อความ): หน้าข่าว (`.hero__media`) และการ์ด (`.spot__card`, `.shot__img`) crop เป็น 4:3, หน้ารวม (`.hub__lead`) 16:9, Facebook/og ราว 1.91:1 — ภาพที่ไม่ใช่ 4:3 จะโดนตัดซ้ายขวา
  - ภาพวาดปก: สั่ง codex แบบ 4:3 วัตถุหลักเต็มตัวอยู่ครึ่งขวา ซ้าย 45% โล่งไว้วางข้อความ
  - ข้อความไทยบนปก (HTML overlay) อยู่ซ้ายกลาง ภายในแถบกลาง y ≈ 180–1020 px (รอด crop 16:9 และ og) และห้ามทับวัตถุหลัก หัวเรื่องยาวให้ขึ้นบรรทัดใหม่
  - ภาพทางการที่ไม่ใช่ 4:3: ครอปให้เต็มกรอบ (ดูข้อ 3 ด้านล่าง ห้ามปล่อยให้เว็บ crop เอง) · ภาพหน้าจอแอป: ใช้ `frame_shots.py --cover` (ข้อ 11) · ภาพหน้าจอเล็ก ๆ ที่อ่านไม่ออกไม่ใช้เป็นปก
  - ตรวจ: เปิดหน้าข่าวที่ 1280 แล้ว screenshot `.hero__media img` ดูว่าไม่มีข้อความ/วัตถุโดนตัด
- ภาพ web: ≤1600px, JPEG q85, ล้าง EXIF · ต้นฉบับเก็บใน `_sources/posts/news/<slug>/` · `python3 scripts/content/thumbs.py`

- เปิดหน้าทางการไม่ได้ (X, status page) ให้บอกในข่าวว่าอ่านคำชี้แจงผ่านสื่อ · คำพูดบริษัทยกภาษาอังกฤษสั้น ๆ แล้วอธิบายไทย · ไม่เดาเรื่องการโจมตี
- ภาพ: ภาพบรรยากาศ 2–3 ภาพ (เช่น คนเปิดเมลไม่ขึ้นตอนดึก, ออฟฟิศเช้าวันทำงาน, วิศวกรในศูนย์ข้อมูล) คู่กับไทม์ไลน์/ผลกระทบ
- รายงานฉบับเต็มของบริษัท (post-incident report) ยังไม่ออก → เพิ่มใน `~/news-digest/followups.md`

## สิ่งที่เจ้าของแก้บ่อย (เช็กก่อนส่งทุกครั้ง) — สรุปจากรอบแก้ข่าวเก่า 14 พ.ย. 2569
1. **ภาพต้องเป็นของจริง:** พื้นหลัง infographic หรือภาพประกอบที่มีสินค้า ต้องเป็นรุ่นจริง (ภาพข่าวแจกของแบรนด์) ห้ามใช้มือถือ/อุปกรณ์ที่วาดขึ้นแล้วหน้าตาไม่ตรงรุ่น · ภาพบรรยากาศที่วาดได้เฉพาะฉาก (คน ออฟฟิศ ศูนย์ข้อมูล) ไม่ใช่ตัวสินค้า
2. **infographic แบบภาพวาดที่ดีอยู่แล้ว เก็บไว้:** แก้ข้อความใน `h.html` แล้ว render ใหม่ ไม่ต้องแปลงเป็น HTML · ข้อความในภาพต้องชัด เช่น "ติดตั้งได้ 2 แบบ" ไม่ใช่ "ติดตั้ง", "สิ่งที่ดูได้" ไม่ใช่ "ดูได้" · ห้ามหัวข้อซ้ำกันในภาพเดียว (เช่น "สหรัฐฯ" สองที่)
3. **ปก 4:3 ต้องเต็มกรอบ:** ภาพข่าวแจกที่กว้างกว่า 4:3 ให้ **ครอป** ถ้าสินค้าอยู่ในกรอบครบ (การเติมขอบบนล่างจะเห็นรอยต่อ) · ภาพหน้าจอรวมหลายหน้าต่าง เลือก 2–3 หน้าต่างแล้วขยายให้เต็มกรอบ ขอบบนล่างเหลือน้อย ตัวหนังสืออ่านได้บนการ์ด
4. **ภาพหน้าจอแถบยาวเตี้ย** (เมนูบาร์ แถบเครื่องมือ) ตัดเป็นชิ้นตามช่องว่างระหว่างโมดูล แล้วเรียงเป็นภาพแนวตั้ง ขยาย 2–3 เท่า ห้ามตัดแยกป้ายกับค่า (เช่น "F: U:" ต้องอยู่กับตัวเลข)
5. **การ์ด `.news-cards` แถวละเรื่อง** (ไม่ทำ 2–3 คอลัมน์ เพราะเบียด)
6. **สเปกมือถือ/อุปกรณ์:** ใช้ `.spec-list` เป็นกรอบแถวละหัวข้อ ไอคอนซ้าย ชื่อหัวข้อเล็ก ค่าตัวใหญ่ แยก ชิป / จอ / กล้อง / แบตเตอรี่ / การชาร์จ (ไม่รวม "ชิปและจอ"): `<div class="spec-list"><div class="spec-row"><svg class="icon spec-icon" aria-hidden="true"><use href="#icon-chip" /></svg><div><b>ชิป</b>Snapdragon …</div></div></div>` ไอคอนที่มี: chip, display, camera, battery, charge, memory, storage, wireless (`src/components/Icons.astro`) เพิ่มใหม่ได้ในไฟล์เดียวกัน วาดเองแบบเส้น · ไม่ใช้ `.grade-grid` แบบเส้นบนสำหรับสเปก (เจ้าของบอกให้มีกรอบ)
7. **รายการ:** ขั้นตอน → `.news-steps` (มีหัวข้อสั้นตัวหนา) · ข้อควรรู้ → `.news-cards` · รายการสั้น 2–3 ข้อแบบ "ใครควรใช้" → เขียนเป็นย่อหน้าเดียว · ข่าวเรื่องเก่าที่กลับมาเป็นข่าว ใส่ `.news-tl` "ทำไมถึงเป็นข่าวตอนนี้"
8. **ที่มาของภาพ** อยู่ในหัวข้อ `## ที่มาของภาพ` แยกจาก `## แหล่งข้อมูล` เสมอ
10. **infographic ของข่าวแอป:** ฉากพาสเทลที่วาดขึ้น มีโน้ตบุ๊ก/จอ/มือถือแบบทั่วไปไม่มียี่ห้อ อยู่หลังการ์ดข้อความ **ใช้ได้และเจ้าของชอบ** (14 พ.ย. 2569: เปลี่ยนเป็นภาพหน้าจอจริงเล็ก ๆ ข้างการ์ดแล้ว เจ้าของสั่งเปลี่ยนกลับ) · ข้อ 1 ใช้กับข่าวที่ตัวอุปกรณ์เป็นเรื่องของข่าว (มือถือรุ่นใหม่ ฯลฯ) · อย่าเปลี่ยนภาพที่เจ้าของเคยผ่านแล้วถ้าเขาไม่ได้สั่ง
11. **ภาพหน้าจอแอป (ปกและในเนื้อข่าว) ให้มีสีสันแต่ไม่ฉูดฉาด:** วางบนพื้นไล่สีพาสเทล (ม่วงอ่อน › ชมพู › พีช โทนเดียวกับ infographic) ขอบมน เงาบาง ตัวภาพหน้าจอไม่แก้ `python3 scripts/content/frame_shots.py SHOT OUT.jpg` (ในเนื้อข่าว) · `python3 scripts/content/frame_shots.py --cover cover.jpg A.png B.png` (ปก 1600×1200 ภาพหน้าจอจริง 1–2 ภาพใหญ่เต็มกรอบ) · ต้นฉบับเก็บใน `_sources/.../body-orig/` · แก้ `width`/`height` ใน mdx ตามขนาดใหม่ · เครดิตเติม "วางบนพื้นสีโดย DOJOJIN.TECH" · ปกห้ามเป็นหน้าต่างเล็กบนพื้นขาวกว้าง
12. **ภาพที่อัดตารางทั้งตารางไว้ข้างใน = แน่นเกิน** (เจ้าของ: "เป็นรูปจ๋าเกินไป"): ในภาพเหลือเฉพาะสิ่งที่ต้องเห็นด้วยตา (เช่น ตัวอย่างฟอนต์ตัวใหญ่ + คำอธิบายบรรทัดเดียว) ส่วนรายละเอียดย้ายลงเนื้อหาเป็น `.news-cards` แถวละเรื่อง · หัวข้อภาพห้ามซ้ำกับภาพก่อนหน้าในหัวข้อเดียวกัน
13. **render infographic:** `render-infographic.mjs` ใช้ viewport กว้าง 640 px (×2.5 = 1600) — `body{width:640px}` ใน `h.html` ไม่งั้นขวาโดนตัด · ดูภาพที่ render ทุกครั้งก่อนส่ง
14. แก้ข่าวเก่าแล้วใส่ `updated:` · ตรวจหน้าจอจริงทั้งโหมดสว่างและมืด ที่ 390 และ 1280 · ดู `.hero__media img` ที่ 1280

## Layout (ภาพอยู่ในเนื้อข่าว ไม่มีแกลเลอรีท้ายข่าว)
- ทุกภาพ (infographic หรือภาพถ่าย) อยู่ใน `<div class="split">` คู่กับ `<div class="prose">` ที่**อธิบายภาพนั้นจริง** · ห้ามซ้อน split · split ละ 2 ลูกพอดี
- ภาพถ่าย: `<figure class="news-fig"><div class="news-fig__img"><img …/></div><figcaption><span class="news-fig__credit">ภาพ: … · <a …>…</a></span></figcaption></figure>`
  - ใต้ภาพมีแค่เครดิต — สิ่งที่ภาพแสดงเขียนเป็นเนื้อข่าวปกติในย่อหน้าคู่ (ใช้คำว่า "ในภาพ" ไม่ใช้ "ภาพด้านบน/ล่าง")
  - ภาพแนวตั้ง: เพิ่ม `news-fig--tall` · ภาพที่มีตัวหนังสือ (หน้าจอ ตาราง ผัง ประกาศ): เพิ่ม `news-fig--zoom` (ได้แว่นขยาย ✕/Esc/คลิกพื้นหลังเพื่อปิด) — infographic ซูมได้อัตโนมัติ
- ซ้าย/ขวาสลับกันทั้งหน้า: รัน `python3 scripts/content/alternate-splits.py src/content/posts/news/<slug>.mdx`
- มือถือ (≤768px) ภาพขึ้นก่อน ตามด้วยข้อความของภาพนั้น (CSS จัดการเอง)
- ข่าวประชาสัมพันธ์ภาพเยอะ: ภาพหลัก 3–4 ภาพในเนื้อข่าว ที่เหลือ `## ภาพเพิ่มเติม` + ShotGallery

## Sitemap / SEO (อัตโนมัติ — ไม่ต้องทำมือ)
- `npm run build` สร้าง `sitemap-index.xml` (ทุกหน้า + `lastmod` จาก `date` ใน frontmatter; ถ้าแก้บทความเก่ามากให้เพิ่ม `updated: 2026-11-20T10:00:00+07:00` แล้ว lastmod จะใช้ค่านี้) และ `news-sitemap.xml` (ข่าว 2 วันล่าสุดสำหรับ Google News) — logic อยู่ใน `astro.config.mjs` และ `src/pages/news-sitemap.xml.js`
- พาดหัว (`title`) และ `description`: ใส่คำที่คนค้นจริง เช่น "รีวิว <รุ่น> … ดีไหม?" + ตัวเลข/จุดเด่นที่วัดได้, description บอกสิ่งที่อ่านแล้วได้ (ราคา สเปก ผลวัด ข้อดีข้อเสีย ควรซื้อไหม) — ห้ามพาดหัวเกินจริง/หลอกคลิก, ไม่เปลี่ยน URL
- รีวิวสินค้าประเภทเดียวกันให้เพิ่มแถวในหน้ารวม: หัวชาร์จ `src/data/chargers.js` (`/compare/chargers/`), หูฟัง `src/data/headphones.js` (`/compare/headphones/`)

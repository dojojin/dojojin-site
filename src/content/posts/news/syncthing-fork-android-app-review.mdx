## Syncthing-Fork คืออะไร

<div class="split">
<div class="prose">

Syncthing คือโปรแกรมซิงก์ไฟล์แบบเปิดซอร์สครับ ไม่มีเซิร์ฟเวอร์กลางเก็บไฟล์ของเรา ไฟล์วิ่งตรงระหว่างอุปกรณ์ที่เราอนุญาตเท่านั้น

หน้า F-Droid อธิบายว่า Syncthing มาแทนบริการซิงก์และคลาวด์แบบปิด ด้วยของที่เปิด น่าเชื่อถือ และกระจายศูนย์ ข้อมูลเป็นของเราคนเดียว เราเลือกเองว่าจะเก็บที่ไหน แชร์กับใคร และส่งยังไง

ส่วน Syncthing-Fork คือแอปที่ห่อ Syncthing ให้ใช้บน Android หน้า F-Droid บอกว่ามีหน้าจอของแอปเอง ไม่ต้องเปิดเว็บ GUI (หน้าตั้งค่าผ่านเบราว์เซอร์) ของ Syncthing

**สำคัญ:** แอปนี้ไม่ใช่บริการคลาวด์ครับ ลงเครื่องเดียวไม่มีประโยชน์ ต้องมี Syncthing อีกเครื่องให้ซิงก์ด้วย เช่น คอมพิวเตอร์ที่ลง Syncthing จาก <a href="https://syncthing.net/downloads/" rel="noopener">syncthing.net</a> หรือมือถือเครื่องที่สองที่ลง Syncthing-Fork

</div>

## Fork ของอะไร และต่างจากแอปทางการอย่างไร

<div class="prose">

ที่ชื่อมีคำว่า "Fork" เพราะแตกออกมาจากแอป Android ตัวทางการของ Syncthing ครับ (fork คือการก๊อปโค้ดโครงการเดิมมาพัฒนาต่อเป็นอีกสาย) ผมตรวจที่ต้นทางแล้ว สรุปได้แบบนี้

- **แอปทางการเลิกพัฒนาแล้ว:** หน้า GitHub ของ <a href="https://github.com/syncthing/syncthing-android" rel="noopener">syncthing/syncthing-android</a> มีประกาศ "Discontinued" ตอนบนสุด บอกว่ารุ่นสุดท้ายบน GitHub กับ F-Droid คือ Syncthing เวอร์ชันธันวาคม 2567 และ repo ถูกเก็บถาวร (archived) ผู้ดูแลให้เหตุผลว่า Google ทำให้การเผยแพร่บน Play ยากหรือแทบเป็นไปไม่ได้ และไม่มีคนดูแลต่อ เรื่องนี้โพสต์ไว้ใน <a href="https://forum.syncthing.net/t/discontinuing-syncthing-android/23002" rel="noopener">ฟอรัมของ Syncthing</a> เมื่อ 20 ตุลาคม 2567
- **Syncthing-Fork แยกออกมาจากแอปนั้น:** README ของ Fork เขียนว่า "forked from syncthing/syncthing-android" และขอบคุณอดีตผู้ดูแลอย่าง Catfriend1, imsodin และ nutomic ใน README ยังมีหัวข้อ "Switching from the deprecated official version" ไว้ให้คนที่ย้ายมาจากแอปทางการ
- **ยังอัปเดตอยู่:** repo ปัจจุบันอยู่ที่ <a href="https://github.com/researchxxl/syncthing-android" rel="noopener">github.com/researchxxl/syncthing-android</a> (ลิงก์เดิมของ Catfriend1 พามาที่นี่) ไม่ได้ถูกเก็บถาวร และหน้า GitHub ขึ้นว่าอัปเดตล่าสุดเมื่อ 12 พฤศจิกายน 2569

ผมไม่เจอข้อความจากทีม Syncthing ที่รับรองแอป Fork นี้โดยตรง เอกสารของ Syncthing บอกแค่กว้าง ๆ ว่ามี "community flavors" หลายแบบที่ใช้แกน Syncthing เดียวกัน สรุปคือ Fork นี้เป็นโครงการของชุมชน ไม่ใช่แอปของทีม Syncthing ครับ

## สิ่งที่ Fork ทำเพิ่มจากแอปทางการ

<div class="prose">

หน้า F-Droid สรุปจุดเด่นของ Fork ไว้เป็นข้อ ๆ ผมเรียบเรียงใหม่ให้อ่านง่ายครับ

- ดูความคืบหน้าการซิงก์ของโฟลเดอร์ อุปกรณ์ และภาพรวมได้จากหน้าจอแอปเลย
- มีโหมด "ซิงก์ทุกชั่วโมง" ช่วยประหยัดแบตเตอรี่
- ตั้งเงื่อนไขการซิงก์แยกตามอุปกรณ์และตามโฟลเดอร์ได้
- มีหน้า Recent changes กดเปิดไฟล์ที่เพิ่งเปลี่ยนได้
- แก้ค่าโฟลเดอร์และอุปกรณ์ได้ ไม่ว่า Syncthing จะทำงานอยู่หรือไม่
- แอปบอกเหตุผลว่าตอนนี้ Syncthing ทำงานหรือไม่ทำงานเพราะอะไร
- ผู้พัฒนาบอกว่าแก้ปัญหา "battery eater" (กินแบตมาก) แล้ว
- ค้นหาอุปกรณ์ Syncthing อื่นในเครือข่ายเดียวกันแล้วเพิ่มได้ง่าย
- รองรับการซิงก์สองทางบนการ์ด SD ภายนอกตั้งแต่ Android 11

ในภาพคือแท็บ Devices แท็บแรกของแอป แต่ละแถวคืออุปกรณ์ที่จับคู่ไว้ บอกชื่อ สถานะ (Syncing, Disconnected) และความเร็วดาวน์โหลดกับอัปโหลด วงกลมข้างชื่อแอปคือภาพรวมความคืบหน้า

ชื่ออุปกรณ์ในภาพเป็นตัวอย่างของผู้พัฒนา ไม่ใช่ของผมนะครับ

## เริ่มใช้: จับคู่มือถือกับคอมพิวเตอร์ แล้วแชร์โฟลเดอร์

<div class="split">
<figure class="split-fig"><img src="/media/posts/news/syncthing-fork-android-app-review/igv-2.jpg" width="1600" height="1400" loading="lazy" alt="อินโฟกราฟิกเริ่มใช้ 4 ขั้น จับคู่มือถือกับคอมพิวเตอร์ ขั้นที่ 1 ติดตั้ง Syncthing ทั้งสองเครื่อง ขั้นที่ 2 คัดลอก Device ID ของอีกเครื่อง หรือสแกน QR ขั้นที่ 3 Add Device ทั้งสองฝั่ง เลือกโฟลเดอร์ที่จะแชร์ ขั้นที่ 4 รอสักครู่ เครื่องเชื่อมกัน ไฟล์เริ่มซิงก์ ต้องทำทั้งสองฝั่ง ไม่งั้นไม่เชื่อมกัน" /></figure>
<div class="prose">

หลักของ Syncthing ตามคู่มือทางการ (Getting Started) คือ สองเครื่องจะคุยกันได้ก็ต่อเมื่อ **ทั้งสองเครื่องใส่ Device ID ของกันและกัน** Device ID คือรหัสประจำเครื่องที่สร้างตอนเปิดโปรแกรมครั้งแรก ไม่ต้องเก็บเป็นความลับ

ในภาพคืออินโฟกราฟิกที่ผมสรุปขั้นตอนไว้ 4 ข้อ รายละเอียดแต่ละข้อมีดังนี้ครับ

1. **ติดตั้งทั้งสองเครื่อง** ฝั่งคอมพิวเตอร์โหลดจาก <a href="https://syncthing.net/downloads/" rel="noopener">syncthing.net/downloads</a> หน้านั้นมีทั้งตัวหลักสำหรับ Windows, macOS, Linux และตัวห่อสำหรับ Windows กับ macOS ที่ใช้ง่ายกว่า ฝั่งมือถือติดตั้ง Syncthing-Fork
2. **ดู Device ID ของอีกเครื่อง** บนคอมพิวเตอร์ เปิดหน้า GUI ที่ http://127.0.0.1:8384 แล้วเลือก Actions → Show ID ส่วนบนมือถือ เปิดเมนูข้างของแอปแล้วแตะ Show device ID
3. **เพิ่มอุปกรณ์ทั้งสองฝั่ง** กด Add Remote Device (บนคอมพิวเตอร์) หรือไอคอนเพิ่มอุปกรณ์ (บนมือถือ) วาง Device ID ของอีกเครื่อง ตั้งชื่อเล่น (ไม่บังคับ) เลือกโฟลเดอร์ที่จะแชร์ แล้วกดบันทึก
4. **รอสักครู่** คู่มือบอกว่าหลังบันทึก อุปกรณ์ใหม่จะขึ้นในรายการ (ตอนแรกยังขึ้นว่าไม่ได้เชื่อมต่อ) แล้วจะเชื่อมกันภายในประมาณ 1 นาที ขั้นที่ 3 ต้องทำทั้งสองฝั่ง ทำฝั่งเดียวจะไม่เชื่อมกัน

พอเชื่อมแล้ว ไฟล์ที่เพิ่มในโฟลเดอร์ที่แชร์ ไม่ว่าฝั่งไหน จะถูกซิงก์ไปอีกฝั่ง

คู่มือเตือนด้วยว่า ถ้าใช้ Syncthing เวอร์ชันที่เสริมฟังก์ชันของระบบ เช่นแอป Android อาจต้องเข้า Web GUI เพื่อเปิดซิงก์โฟลเดอร์หรือตั้งค่าบางอย่าง

ผมยังไม่ได้ลองซิงก์จริงบนเครื่องตัวเองนะครับ ขั้นตอนข้างบนเรียบเรียงจากคู่มือทางการและภาพหน้าจอของแอป

</div>
</div>

<div class="prose">

ในภาพคือเมนูข้างของแอป เปิดจากไอคอนสามขีดมุมซ้ายบน เมนูที่ใช้บ่อยคือ

- **Show device ID** ดู Device ID ของมือถือเครื่องนี้ เอาไปวางบนคอมพิวเตอร์
- **Recent changes** ดูไฟล์ที่เพิ่งเปลี่ยน
- **Web GUI** เปิดหน้าตั้งค่าเต็มของ Syncthing
- **Import and Export** สำรองหรือกู้คืนค่าตั้งค่า

## ตรวจสถานะและเงื่อนไขการทำงาน

<div class="split">
<div class="prose">

ในภาพคือแท็บ Status บอกว่าตอนนี้ Syncthing ทำงานอยู่หรือเปล่า พร้อมเหตุผลเป็นข้อ ๆ ตัวอย่างในภาพกำลังทำงาน เพราะเครื่องต่อ Wi-Fi ที่ไม่จำกัดปริมาณ (non-metered) อยู่ และแอปตั้งไว้ว่าไม่ซิงก์บนข้อมูลมือถือ ช่วยกันเน็ตมือถือหมดแบบไม่ตั้งใจครับ

ปุ่มด้านบนมี 3 โหมด

- **Follow run conditions** ทำตามเงื่อนไขที่ตั้งไว้
- **Force start ignore run conditions** บังคับเริ่ม ไม่สนเงื่อนไข
- **Force stop ignore run conditions** บังคับหยุด

ด้านล่างยังเห็นเวลาที่ทำงาน (Uptime) การใช้ RAM (107.5 MiB ในภาพตัวอย่าง) และความเร็วดาวน์โหลด

## เทียบกับ LocalSend ที่แนะนำไปก่อนหน้านี้

<div class="prose">

ผมเคยแนะนำ <a href="/news/localsend-app-review/">LocalSend</a> ไปแล้ว สองแอปนี้ดูคล้ายกัน แต่เหมาะกับคนละงานครับ

| | LocalSend | Syncthing-Fork |
|---|---|---|
| งานหลัก | ส่งไฟล์ครั้งเดียวหาเครื่องใกล้ ๆ | ซิงก์โฟลเดอร์ต่อเนื่องระหว่างเครื่องที่จับคู่ไว้ |
| ตั้งค่า | เปิดแอปทั้งสองเครื่อง ส่งได้เลย | จับคู่ด้วย Device ID ทั้งสองฝั่ง แล้วเลือกโฟลเดอร์ |
| เครือข่าย | Wi-Fi หรือ LAN วงเดียวกัน ไม่ต้องใช้อินเทอร์เน็ต | ใช้ในวงเดียวกันได้ และตามเอกสารมีเซิร์ฟเวอร์ค้นหา (discovery) ช่วยหาเครื่องที่อยู่นอกวง |
| ฝั่งที่ต้องลง | LocalSend ทั้งสองเครื่อง | Syncthing ทั้งสองเครื่อง |

ผมว่าถ้าแค่อยากส่งรูปไม่กี่ใบเข้าคอมตอนนี้ LocalSend ง่ายกว่า แต่ถ้าอยากให้โฟลเดอร์ เช่น รูปถ่ายหรือโน้ต ตรงกันเองทุกครั้งที่มีไฟล์ใหม่ Syncthing เหมาะกว่า แลกกับต้องตั้งค่ามากกว่าครับ

## ข้อควรรู้ก่อนใช้

<div class="prose">

- **เป็นการซิงก์ ไม่ใช่การสำรองข้อมูล:** ลบไฟล์ฝั่งหนึ่ง อีกฝั่งก็อาจถูกลบตาม ข้อนี้ผมสรุปจากหลักการซิงก์ทั่วไป ไม่ใช่ข้อความใน README ถ้าต้องการสำรอง ให้ตั้งโฟลเดอร์เป็นแบบส่งอย่างเดียวหรือรับอย่างเดียว และอ่านเอกสารของ Syncthing เรื่องประเภทโฟลเดอร์ก่อนใช้กับไฟล์สำคัญ
- **เครื่องต้องเปิดอยู่ทั้งสองฝั่ง:** ไม่มีเซิร์ฟเวอร์กลางเก็บไฟล์ ถ้าคอมปิดอยู่ มือถือก็ไม่มีที่ส่งไป จนกว่าคอมจะเปิดใหม่
- **การเข้ารหัส:** เอกสารความปลอดภัยของ Syncthing บอกว่าการรับส่งระหว่างอุปกรณ์ป้องกันด้วย TLS (การเข้ารหัสแบบเดียวกับเว็บ https) และเชื่อมต่อได้เฉพาะอุปกรณ์ที่อยู่ในรายการอนุญาต (ตรวจจากลายนิ้วมือใบรับรองของ Device ID)
- **การค้นหาผ่านเซิร์ฟเวอร์กลาง:** เอกสารเดียวกันบอกว่า ค่าเริ่มต้นเปิด Global Discovery ไว้ ซึ่งจะส่งรหัสอุปกรณ์กับพอร์ตไปที่เซิร์ฟเวอร์ค้นหา ไม่สบายใจก็ปิดได้ แต่เครื่องที่อยู่นอกวงเครือข่ายเดียวกันจะหากันไม่เจอ
- **ต้องปรับค่าแบตเตอรี่ของมือถือ:** หน้า GitHub มีบทความแยกตามผู้ผลิตเครื่อง (manufacturer specific) สำหรับเครื่องที่ระบบชอบปิดแอปเบื้องหลัง ผมยังไม่ได้ลองกับเครื่องรุ่นไหนครับ
- **ขอความช่วยเหลือ:** README ขอให้ถามในฟอรัมหรือโซเชียลก่อนเปิด issue บน GitHub

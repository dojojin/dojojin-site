## ขั้น 8: ต้องผ่านครบก่อนส่งเจ้าของ

```bash
python3 scripts/content/check-splits.py src/content/posts/news/<slug>.mdx   # โครงหน้า
VOICE_BASE=<โฟลเดอร์สำเนาก่อนเกลา> python3 scripts/content/check-voice-pass.py <slug>   # เกลาแล้วตัวเลข/ลิงก์ไม่เปลี่ยน
python3 scripts/content/check-sources.py <slug>     # แหล่งข้อมูล (ลิงก์เปิดได้ ชื่อสื่อมีลิงก์ครบ เกณฑ์ 2 แหล่ง facts.md)

npm run build && npm run lint
```
แล้วเปิดหน้าจริงที่ 390 / 768 / 1280 ดูภาพหน้าจอ และเปิดดูปกทุกภาพด้วยตา

## บทเรียนจากรอบนี้
- สรุปข่าวมักเขียนแรงกว่าต้นทาง (เช่น "critical" ทั้งที่ผู้ผลิตให้ High, "ลดแรม" ทั้งที่บริษัทพูดว่า "อาจ") ผู้ร่างต้องเขียนตามต้นทาง และรายงานจุดที่สรุปข่าวคลาด
- ข้อที่สรุปข่าวขึ้นว่า "สื่อเจ้าเดียว" ให้หาต้นทางทางการก่อนเขียน (ข่าวแจก release notes คำสั่งศาล วิดีโอของบริษัท) หาไม่ได้ให้หยุดและรายงาน
- ใน MDX เซลล์ตาราง `<td>…</td>` ต้องอยู่บรรทัดเดียว และใช้ `<br />` ไม่ใช่ `<br>` ไม่งั้น build ล้ม
- คำยาวติดกันในกล่องตัวเลข (`news-stat` ตัวหนา) ทำให้หน้าล้นจอ ให้ใส่คำสั้นในตัวหนา คำอธิบายไว้ข้างล่าง
- tag ใช้ได้เฉพาะที่มีใน `TAGS` (`src/data/site.js`) ผู้ร่างห้ามแก้ไฟล์นั้นเอง ให้รายงาน tag ที่ขาด แล้วคนคุมงานเพิ่มหลังเจ้าของเห็นชอบ

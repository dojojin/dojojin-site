# มาตรฐานบรรณาธิการ DOJOJIN.TECH

ฉบับ 26 พ.ย. 2569 · ใช้กับ**ทุกเครื่องมือ** (Claude Code, Codex, Antigravity/agy, ChatGPT, คน)
เอกสารนี้คือฉบับหลักเรื่อง **การเลือกข่าว · การเขียน · สำนวนเจ้าของเว็บ · ปก · การตรวจ**
รายละเอียดเชิงเทคนิคของหน้าเว็บ (class, สคริปต์, layout) อยู่ใน [`news-writing-guide.md`](./news-writing-guide.md) ·
กติกาโปรเจกต์ (deploy, responsive, ความเร็ว) อยู่ใน [`../CLAUDE.md`](../CLAUDE.md) · ถ้าขัดกัน เอกสารนี้ชนะในเรื่องเนื้อหา

## 0. กฎเหล็ก 10 ข้อ (อ่านแค่นี้ก็ห้ามพลาด)

1. **เจ้าของเลือกข่าวก่อนเสมอ** ห้ามเขียนข่าวที่เจ้าของยังไม่ได้เลือก
2. **ห้ามแต่งข้อมูล** ตัวเลข ราคา วันที่ รุ่น คำพูด ต้องมาจากหน้าเว็บที่เปิดอ่านเองจริง ผลสรุปจากการค้น (search summary) ไม่นับ
3. **ห้ามข่าวแหล่งเดียว** ต้องมีต้นทางทางการ หรือสื่ออิสระ 2 เจ้าขึ้นไป (ดูข้อ 2)
4. **ห้ามแต่งประสบการณ์ของเจ้าของ** ทั้งทางบวกและลบ ("ผมลองแล้ว", "ผมยังไม่เคยใช้") ถ้าเจ้าของไม่ได้บอก
5. **เขียนเป็นเสียงเจ้าของ** ไทยง่าย ๆ ผม/ครับ ไม่มี emoji บนเว็บ (ดูข้อ 4)
6. **ห้ามเขียนคำว่า AI / Codex / ChatGPT / Canva / NanoBanana** ในเครดิตภาพ alt หรือในภาพ · ภาพที่สร้างเอง = "ภาพประกอบจาก DOJOJIN.TECH" · ภาพปก = "by dojojin.tech" (ชื่อผลิตภัณฑ์ในเนื้อข่าว เช่น "OpenAI ใช้ Codex" เขียนได้ตามปกติ)
7. **ห้ามใช้ภาพจากสำนักข่าวไทย**
8. **ปกต้องมี CI ของเรื่องนั้น** โลโก้/ไอคอนจริง + สีของแบรนด์ ขนาด 1600×1200 (ดูข้อ 5)
9. **ห้าม commit / push / deploy เองโดยเจ้าของไม่ได้สั่ง** push ขึ้น `main` = ขึ้นเว็บจริงทันที · commit ใช้ชื่อเจ้าของคนเดียว ไม่มี trailer `Co-Authored-By`
10. **ความลับ:** ห้ามพูดถึง Vigil Platform/Vigil Mobile เชิงเทคนิค ห้ามลิงก์ repo ที่ยังปิด ห้าม commit `_sources/` ห้ามพิมพ์รหัส/โทเคน

## 1. ขั้นตอนงานข่าว (เหมือนกันทุกเครื่องมือ)

| ขั้น | ใครทำ | ผลลัพธ์ |
|---|---|---|
| 1. สรุปหัวข้อ (digest) | cron 08:20 / 16:20 → `~/news-digest/YYYY-MM-DD-HHMM.md` (prompt: `~/news-digest/prompt.md`) | รายการมีเลขต่อเนื่อง บอกจำนวนแหล่งทุกข้อ |
| 2. เลือก | **เจ้าของ** ตอบเป็นเลข | |
| 3. ค้นและตรวจ | agent | `facts.md` ต่อข่าว: ข้อเท็จจริง \| URL \| ข้อความคัดจากหน้านั้น |
| 4. ร่าง | agent | `src/content/posts/news/<slug>.mdx` + ภาพ |
| 5. เกลาสำนวน | **agent อีกตัว** (ไม่ใช่ตัวที่ร่าง) | เสียงเจ้าของ ข้อเท็จจริงไม่เปลี่ยน |
| 6. ตรวจ | agent หลัก | รายการตรวจข้อ 7 ผ่าน |
| 7. เจ้าของตรวจ | **เจ้าของ** ดู preview | |
| 8. commit → deploy | เมื่อเจ้าของสั่งเท่านั้น | |

- ข่าวที่ยังมีเรื่องค้าง (รอราคาไทย รอแพตช์ รอรายงาน) → เพิ่มบรรทัดใน `~/news-digest/followups.md`
- ข่าวเดิมที่มี**ข้อมูลใหม่จริง** → เพิ่มบล็อก "อัปเดต <วันที่>" + `updated:` + `bumped:` (ค่าเดียวกัน) · แก้คำเฉย ๆ ใส่แค่ `updated:`
- ถ้าเจ้าของสั่ง "ปักหมุด" ใช้ `pinned: true`

## 2. การเลือกข่าวและเกณฑ์แหล่งข้อมูล

**หมวดที่ตาม:** A ความปลอดภัยไซเบอร์ · B กล้องวงจรปิด/VMS · C มือถือ · D เทคโนโลยี/AI · E ข่าวประชาสัมพันธ์ในเมล · F ซอฟต์แวร์ · G แอปแนะนำ · H รถ EV · I ติดตามข่าวเดิม · J สื่อไทย (ใช้เป็นเบาะแสเท่านั้น)

**เกณฑ์ "ลงได้"**

| สถานการณ์ | ต้องมี |
|---|---|
| เจ้าของเรื่องประกาศเอง (ข่าวแจก หน้าเว็บ advisory repo) | เปิดหน้านั้นอ่านเอง 1 แหล่งก็พอ |
| เจ้าของเรื่อง**ไม่ได้**ประกาศเอง (ข่าวลือ รายงานอ้างแหล่งข่าว) | สื่ออิสระ **2 เจ้าขึ้นไป** ที่มีข้อมูลของตัวเอง + เขียนในข่าวว่าบริษัทยังไม่ยืนยัน |
| หลายสื่อรายงานต่อจากสื่อเดียว (เช่นทุกเจ้าอ้าง FT) | **นับเป็น 1 แหล่ง → ไม่ลง** (กรณีจริง: ข่าว Nvidia ระงับส่งเซิร์ฟเวอร์ 26 พ.ย. ถูกลบ) |
| ข่าวแจก PR ที่หลายเว็บลงพร้อมกัน | ต้นทาง = บริษัท นับ 1 แต่ลงได้เพราะเป็นต้นทาง |
| สื่อไทยเจ้าเดียว | ไม่ลง จนกว่าจะเจอต้นทางหรือเจ้าที่สอง |

**ไม่เสนอ / ต้องถามก่อน**
- งานหรือโปรที่ผ่านไปแล้ว หรือเหตุการณ์เก่าหลายวันที่ข้อมูลยังบาง → บอกเจ้าของก่อนร่าง
- ข่าวลือ: ติดป้าย "ข่าวลือ" ในหัวข่าว และบอกว่าใครเป็นคนพูด
- ข่าวกล้อง: เป็นกลางระหว่างยี่ห้อ ห้ามพูดถึงลูกค้าหรือระบบของเจ้าของ
- **ราคาไทย:** หาหน้าทางการของแบรนด์ในไทยก่อน (เช่น samsung.com/th) สื่อไทยใช้ยืนยันเสริม · ไม่เจอราคาไทย = เขียนตรง ๆ ว่ายังไม่ประกาศ ห้ามแปลงค่าเงินแล้วเรียกว่าราคาไทย

## 3. การตรวจข้อเท็จจริง

- เปิดต้นทางเองทุกครั้ง เว็บที่เปิดไม่ได้: เว้นช่วงแล้วลองใหม่ (ไม่เกิน 3 ครั้ง) → ลอง RSS / Wayback → ใช้สื่ออื่น
- ทุกแหล่งในหัวข้อ "แหล่งข้อมูล" ต้องเป็น**ลิงก์ที่เปิดอ่านแล้วจริง** ห้ามใส่แค่หน้าแรกของเว็บ ห้ามใส่ชื่อสื่อที่ไม่ได้เปิด ห้ามคำว่า "memory"
- คำเด็ดขาด ("100%", "รุ่นแรกของโลก", "ปลอดภัย", "ทั้งหมด") ต้องบอกว่า**ใครเป็นคนพูด** เช่น "1Password ระบุว่า Vault ไม่ถูกเข้าถึง"
- คำอ้างของผู้ผลิต (คะแนนทดสอบ ความเร็ว อายุแบต) เขียนว่าเป็นตัวเลขของผู้ผลิตเอง
- **โอเพนซอร์ส:** เช็กไฟล์ LICENSE ก่อนใช้คำนี้และก่อนใส่ tag `open-source` (Keka, Pearcleaner เคยผิด: source-available ไม่ใช่โอเพนซอร์ส)
- **แอป/ซอฟต์แวร์:** เช็กวันออกรุ่นล่าสุดและสถานะโครงการ (ยังพัฒนาอยู่ไหม) ระบบที่รองรับขั้นต่ำ และแหล่งโหลดทางการ
- สเปกที่แต่ละแหล่งไม่ตรงกัน: ใช้ค่าที่ต้นทางยืนยัน บอกว่าแหล่งไหนต่าง ห้ามทิ้งโน้ตถึงเจ้าของไว้ในข่าว ("ให้เช็กอีกที")
- เวลา: แปลงเป็นเวลาไทยเองและบอกว่าแปลง · ปี พ.ศ. นำ
- ผลกระทบในไทย: ใช้หลักฐานจริงเท่านั้น ไม่เจอให้เขียนว่า "ยังไม่พบ"
- ส่วนที่คำนวณหรืออธิบายเอง ติดป้าย "(ผมคำนวณเอง)" / "(ข้อนี้เป็นความเห็นผม)"
- แก้ข่าวเก่าแล้วต้องอ่านทั้งเรื่องซ้ำ: ประโยค "ยังไม่…" ที่หมดสถานะแล้วต้องแก้ให้ตรงกับอัปเดต

## 4. สำนวนเจ้าของเว็บ

อ่านตัวอย่างจริงก่อนเขียนทุกครั้ง: `src/content/posts/review/hoco-q47.mdx`, `review/anitech-h9313.mdx`, `knowledge/usb-charger-data-pins.mdx`

**ลักษณะ**
- สรรพนาม "ผม" ลงท้าย "ครับ" (ไม่ต้องทุกประโยค) เล่าตรงกับคนอ่าน
- ประโยคสั้น ประเด็นมาก่อนรายละเอียด ย่อหน้าละ 1–3 ประโยค
- ศัพท์เทคนิคและตัวย่ออธิบายตอนเจอครั้งแรก: "CVE (เลขทะเบียนช่องโหว่สากล)", "พูดง่าย ๆ คือ…"
- ตัวเลขหรือชื่อหลายตัว ทำเป็นรายการหรือกล่อง HTML ไม่อัดในประโยคเดียว
- มีความเห็นสั้น ๆ ได้ ("ผมว่า…") และบอกว่าเป็นความเห็น
- เป็นมิตรกับแบรนด์ ไม่เชียร์ ไม่โจมตี ไม่มีคำโฆษณา
- ชื่อคนใช้ชื่อเต็ม (Elon Musk ไม่ใช่ Musk)
- คำพูดภาษาอังกฤษใน " " ต้องมีคำแปลไทยตามทันที

**ห้าม**
- emoji บนเว็บ (โพสต์ Facebook ใช้ได้ตามรูปแบบของเจ้าของ)
- สำนวนแปล สำนวนข่าวแจก ("มุ่งมั่น", "ตอกย้ำ", "ยกระดับประสบการณ์")
- เล่าขั้นตอนการทำงานในเนื้อข่าว ("ผมเปิดหน้านั้นไม่ได้", "403", "ต้นฉบับ") · ข้อจำกัดเขียนให้คนอ่าน: "ผมหาเอกสารยืนยันไม่เจอ"
- อ้างสื่อซ้ำทุกวลี: อ้างแต่ละแหล่งครั้งเดียวต่อเรื่อง
- คำกำกวม เช่น "คะแนนเสียง" → "คะแนนคุณภาพเสียง"

**แยกตามประเภท**

| ประเภท | จุดต่าง |
|---|---|
| ข่าว | ตามข้อ 1–3 · มีหัวข้อ `## แหล่งข้อมูล` และ `## ที่มาของภาพ` (class `section sources`, ตัวเล็ก) |
| ข่าวเหตุการณ์ (ระบบล่ม โจมตี) | สรุปสั้น → ไทม์ไลน์เวลาไทย → กระทบอะไร → คนไทยโดนไหม → สาเหตุตามที่บริษัทแจ้ง → ทำอย่างไร |
| แอปแนะนำ | `section: app` + tag `app` · บอกราคา ระบบที่รองรับ วิธีลง ขั้นตอนใช้ครั้งแรก ข้อจำกัด |
| ความรู้ | ลงลึกแต่ย่อยง่าย · ที่มาที่ไป → ทดลองอะไร → นำไปสู่อะไร · ภาพจริงทุกสิ่งที่เอ่ยชื่อ · มีภาพหรือกล่องทุกหนึ่งจอมือถือ |
| รีวิว | เป็นรีวิวของเจ้าของ: รีวิวของคนอื่นใช้เป็นข้อมูลเท่านั้น **ไม่ใส่ลิงก์/เครดิต** · สเปกบอกที่มา (ฉลาก/กล่อง/มิเตอร์) · ช่องทางขายใช้ปุ่มโลโก้ Shopee |

## 5. ปกและภาพ

**ปก (ทุกประเภทบทความ)**
- ขนาด **1600×1200 (4:3)** เต็มกรอบ ไม่มีขอบขาวรอบนอก
- **CI ของเรื่อง:** โลโก้หรือไอคอน**ของจริง** (ไฟล์จากหน้า press/brand ของบริษัท หรือ repo ของแอป) + โทนสีหลักของแบรนด์ · ข้อยกเว้น: ข่าวที่โลโก้จะทำให้แบรนด์ดูเป็นผู้ร้าย ให้ถามเจ้าของ
- ข่าวสินค้า: ใช้ภาพทางการของรุ่นจริง ห้ามวาดสินค้าขึ้นใหม่ให้หน้าตาผิดรุ่น
- พื้นมืดใช้เฉพาะข่าวความปลอดภัยไซเบอร์ นอกนั้นพื้นสว่าง
- ข้อความบนปก: หัวเรื่องใหญ่ 2–3 บรรทัด + ป้ายหมวดเล็ก + แถบเน้น 1 อัน + ชิป 2–3 อัน · ระยะบนกับล่างเท่ากัน · วัตถุหลักอยู่ในกรอบครบ ไม่โดนชิปบัง
- **ข้อความบนปกต้องตรงกับเนื้อข่าว** ทุกคำ (ตัวเลข รุ่น คำอ้าง) ถ้าแก้ข่าวแล้วปกผิด ต้องแก้ปกด้วย
- ห้ามปกตัวหนังสือล้วน

**วิธีทำปก (เลือกตามเครื่องมือที่มี ผลลัพธ์ต้องผ่านเกณฑ์เดียวกัน)**

| วิธี | ใช้เมื่อ | หมายเหตุ |
|---|---|---|
| `scripts/content/photo_cover.py` + `render_cover.mjs` | มีภาพจริง/ภาพทางการ | ทุกเครื่องมือใช้ได้ · spec ตัวอย่างใน `_sources/posts/news/*/cover-v2/` · `text_top: 90`, `chips_bottom: 90` |
| สร้างภาพทั้งปกด้วยเครื่องมือสร้างภาพ (ChatGPT Image ผ่าน `codex exec`, NanoBanana ใน agy) | แอปแนะนำ หรือข่าวที่ไม่มีภาพจริง | แนบไอคอน/โลโก้จริงเป็นภาพอ้างอิง + ปกที่ผ่านแล้วเป็นตัวอย่างสไตล์ · ระบุข้อความไทยทุกคำแบบ exact · สั่ง "ไม่มีคน ไม่มีมือ ไม่มีลายน้ำ" · เก็บ prompt ไว้ที่ `_sources/posts/news/<slug>/cover-chatgpt/` |
| Canva (`copy-design` จากแม่แบบ → `edit-design`) | ต้องการเลย์เอาต์นิตยสารสม่ำเสมอ | ดู `news-writing-guide.md` |

`codex exec` ต้องส่ง prompt ทาง stdin เมื่อแนบภาพ: `codex exec --skip-git-repo-check -s workspace-write -i icon.png -i style-ref.jpg - < prompt.txt`

ตัวอย่างปกที่ผ่านแล้ว (ใช้เป็นภาพอ้างอิงสไตล์): `public/media/posts/news/keka-macos-app-review/cover.jpg`, `public/media/posts/news/pearcleaner-macos-app-review/cover.jpg`

**ตรวจภาพที่สร้างทุกภาพด้วยตาก่อนใช้:** ตัวสะกดและวรรณยุกต์ไทย โลโก้/ไอคอนตรงของจริง มือ นิ้ว ใบหน้า ตัวหนังสือมั่ว ขอบขาว

**ภาพในเนื้อหา**
- ทุกข่าวมีภาพในเนื้อข่าวอย่างน้อย 1 ภาพ คู่กับย่อหน้าที่อธิบายภาพนั้น
- ที่ใช้ได้: ภาพทางการของแบรนด์ ภาพหน้าจอจริง Wikimedia Commons (ระบุผู้ถ่าย+สัญญาอนุญาต) สื่อต่างประเทศ (เครดิต+ลิงก์) ภาพประกอบฉากที่สร้างเอง
- ข้อมูล ตาราง ไทม์ไลน์ ตัวเลข = **HTML ในเนื้อข่าว** (เข้ากับโหมดสว่าง/มืด) ไม่ทำเป็นรูป
- เบลอป้ายทะเบียน ใบหน้า รูปโปรไฟล์ QR/serial (ยกเว้น QR บนเครื่องหมาย มอก.) · ล้าง EXIF/GPS · ≤1600px
- เครดิตทุกภาพใน `## ที่มาของภาพ`

## 7. รายการตรวจก่อนส่งเจ้าของ

- [ ] ทุกตัวเลข/วันที่/คำพูด มีแหล่งที่เปิดแล้วใน `facts.md` หรือรายงาน
- [ ] ผ่านเกณฑ์แหล่งข้อมูลข้อ 2 · `sourceName` ไม่ใช่สื่อเจ้าเดียว
- [ ] หัวข่าว description lead เนื้อหา ตาราง ปก **พูดตรงกัน**
- [ ] ไม่มีโน้ตภายใน ไม่มีประโยคหมดสถานะ ไม่มีคำเด็ดขาดที่ไม่ระบุผู้พูด
- [ ] ผ่านการเกลาสำนวนโดย agent อีกตัว · ไม่มี emoji · ไม่มีคำว่า AI/Codex ในเครดิต
- [ ] tag อยู่ใน `TAGS` (`src/data/site.js`) · `date` มีเวลา · แก้ข่าวเก่าใส่ `updated`
- [ ] `python3 scripts/content/thumbs.py` · `python3 scripts/content/check-splits.py <ไฟล์>` = OK
- [ ] `npm run build` และ `npm run lint` ผ่าน
- [ ] เปิดหน้าจริงที่ 390 / 768 / 1280: ไม่มี scroll แนวนอน และ**ดูภาพหน้าจอจริง**
- [ ] ดูปกด้วยตา: 4:3 เต็มกรอบ CI ถูก ข้อความถูก
- [ ] รายงานเจ้าของเป็นภาษาไทย แยก 🔵 Fact / 🟡 Opinion: ตรวจอะไรแล้ว · อะไรยังยืนยันไม่ได้ · อะไรไม่ผ่านเกณฑ์
- [ ] **รอเจ้าของสั่ง** ก่อน commit และก่อน deploy

## 8. เมื่อเจ้าของสั่งกติกาใหม่

เขียนลงเอกสารนี้ (หรือ `news-writing-guide.md` ถ้าเป็นเรื่องเทคนิคหน้าเว็บ) พร้อมวันที่และคำพูดของเจ้าของ เพื่อให้ทุกเครื่องมือเห็นตรงกัน ไม่เก็บไว้ในความจำของเครื่องมือตัวใดตัวหนึ่งอย่างเดียว

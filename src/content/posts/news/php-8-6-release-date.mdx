## ตอนนี้อยู่ตรงไหน

<div class="split">
<div class="prose">

วันที่ 12 พฤศจิกายน 2569 ทีม PHP ปล่อย PHP 8.6.0 RC7 (Release Candidate รุ่นทดสอบก่อนตัวจริง) ออกมาให้ทดสอบ

รุ่นถัดไปจะเป็นตัวจริงตัวแรก หรือ GA (General Availability) คือ **PHP 8.6.0 กำหนดวันที่ 19 พฤศจิกายน 2569**

ตอนที่ผมเขียนข่าวนี้ (14 พ.ย.) ตัวจริงยังไม่ออกนะครับ ยังเป็นแค่กำหนดการ และตารางงานของ PHP เองก็เขียนไว้ว่ารุ่นต่าง ๆ อาจถูกเพิ่มหรือตัดได้ระหว่างทาง

เลข RC อาจดูงงนิดนึง

- RC1 ไม่เคยออกจริง (แพ็กไฟล์ผิดพลาด เลยออกเป็น RC2 แทน)
- RC6 ถูกแท็กแล้วข้ามไป
- ประกาศเลยเรียก RC7 ว่า "รุ่นทดสอบที่ห้า"

ในภาพผมสรุปไทม์ไลน์ตั้งแต่ RC4 จนถึงวันออกตัวจริงไว้ให้ครับ

ประกาศเขียนตรง ๆ ว่า **"Please DO NOT use this version in production"** ครับ อยากลองก็ลองในเครื่องทดสอบหรือ staging เท่านั้น

</div>

## ของที่อาจทำให้เว็บเดิมพัง

<div class="split">
<figure class="split-fig"><img src="/media/posts/news/php-8-6-release-date/igv-2.jpg" width="1600" height="1540" loading="lazy" alt="อินโฟกราฟิกสิ่งที่ต้องเช็กก่อนอัป PHP 8.6 ค่า session ใหม่ use_strict_mode=1, cookie_httponly=1, cookie_samesite=Lax, trim() ตัด form feed, preg_grep() คืน false เมื่อผิดพลาด, deprecated: return ใน finally, define() อาร์กิวเมนต์ที่สาม, spl_object_hash(), mbregex" /></figure>
<div class="prose">

ส่วนนี้ผมว่าเจ้าของเว็บควรอ่านที่สุด มาจากหมวด Backward Incompatible Changes (เปลี่ยนแล้วโค้ดเดิมอาจพัง) กับ Deprecated ในไฟล์ UPGRADING ผมยกมาเฉพาะข้อที่น่าจะกระทบเว็บทั่วไป

ในภาพผมรวมรายการที่ต้องเช็กไว้ในหน้าเดียว รายละเอียดตามนี้ครับ

**ค่า session เปลี่ยนค่าเริ่มต้น** เป็น `session.use_strict_mode=1`, `session.cookie_httponly=1` และ `session.cookie_samesite=Lax`

ปลอดภัยขึ้นครับ แต่ถ้าแอปเก่าพึ่งพฤติกรรมเดิม เช่น ให้ JavaScript อ่านคุกกี้ session ก็อาจพังได้

**`trim()` ตัด form feed** ด้วยเป็นค่าเริ่มต้น

**`preg_grep()`** คืนค่า false เมื่อ regex ทำงานผิดพลาด แทนที่จะคืนอาร์เรย์ครึ่ง ๆ กลาง ๆ

**ฟังก์ชันจำนวนมากโยน `ValueError`** เมื่อรับสตริงที่มี NUL byte เช่น `getenv()`, `parse_str()`, `proc_open()`

**ที่ถูกประกาศเลิกใช้ (deprecated)** ตอนนี้ยังใช้ได้ แต่จะขึ้นคำเตือน เช่น

- `return` ใน `finally`
- อาร์กิวเมนต์ตัวที่สามของ `define()`
- `spl_object_hash()` (ให้ใช้ `spl_object_id()` แทน)
- `mbregex` และ `metaphone()`
- การตั้งชื่อฟังก์ชันว่า `readonly`

</div>

## วันที่ 19 พ.ย. ผู้ดูแลเว็บควรทำอะไร

<div class="prose">

ผมแนะนำตามนี้ครับ

1. **อย่าเพิ่งอัปเกรด production วันแรก** รอตัวจริงออกก่อน แล้วรอให้ framework กับปลั๊กอินที่ใช้ประกาศว่ารองรับ 8.6
2. **เช็กความเข้ากันได้** ของ framework, CMS, ปลั๊กอิน และ extension ที่เซิร์ฟเวอร์ใช้ ไล่ดู changelog หรือหน้า requirement ของแต่ละตัว ตัวไหนรองรับแล้วบ้างผมเองก็ยังไม่รู้ครับ ต้องดูจากผู้พัฒนาแต่ละราย
3. **ทดสอบบน staging** เปิด `error_reporting` ให้เห็น deprecation แล้วไล่แก้คำเตือนที่ขึ้น
4. **ใช้โฮสติ้ง?** รอผู้ให้บริการเปิดตัวเลือก 8.6 ในหน้าควบคุมได้เลย ไม่ต้องทำอะไรก่อน
5. **ใช้ 8.5, 8.4 ต่อไปได้** แต่อย่าลืมลงแพตช์ความปลอดภัยเสมอ ดูเรื่อง <a href="/news/php2shell/">PHP2Shell</a> ที่เพิ่งแก้ไป ซึ่งทีม PHP ระบุว่า RC4 ของ 8.6.0 ก็มีแพตช์ชุดนี้แล้ว

คนทั่วไปที่แค่เข้าเว็บไม่ต้องทำอะไรเลยครับ

</div>

## เกิดอะไรขึ้น

<div class="split">
<div class="prose">

วันที่ 18 พฤศจิกายน 2569 ทีมความปลอดภัยของ Drupal ออกประกาศ SA-CORE-2026-017 แจ้งช่องโหว่ระดับ Critical ใน Drupal core เลข CVE-2026-132165

ไฟล์ <code>install.php</code> คือตัวติดตั้งเว็บของ Drupal core ครับ ประกาศบอกว่าในบางเงื่อนไข ผู้โจมตีใช้ไฟล์นี้พยายามติดตั้ง Drupal ทับเว็บที่มีอยู่ได้ ผลคืออาจยึดเว็บ หรือสั่งรันโค้ดบนเซิร์ฟเวอร์ได้

คะแนนความเสี่ยงตามระบบของ Drupal คือ 18 จาก 25 อยู่ในระดับ Critical ส่วน "บางเงื่อนไข" นั้นคืออะไร ประกาศไม่ได้บอกไว้

มีจุดหนึ่งที่ช่วยได้ ถ้าเว็บเซิร์ฟเวอร์เขียนหรือเปลี่ยนสิทธิ์ไฟล์ <code>settings.php</code> ไม่ได้ ประกาศบอกว่าบางวิธีโจมตีจะไม่สำเร็จ

คนที่เจอช่องโหว่นี้ ประกาศระบุว่าเป็นเครื่องมือ OSS Scanner ของ Anthropic

รุ่นที่โดนตามประกาศ คือ ต่ำกว่า 10.6.22, ตั้งแต่ 11.0.0 ถึงต่ำกว่า 11.3.22 และตั้งแต่ 11.4.0 ถึงต่ำกว่า 11.4.13

## ถูกโจมตีจริงหรือยัง

<div class="prose">

ThaiCERT บอกว่ายังไม่มีรายงานยืนยันว่ามีคนเอาช่องโหว่นี้ไปโจมตีจริง เว็บข่าวความปลอดภัย SecurityOnline ก็รายงานตรงกันว่ายังไม่พบการโจมตี

แต่อย่าเพิ่งวางใจครับ ในคะแนนของ Drupal ช่อง exploit maturity เขียนว่า <code>E:Proof</code> ผมเข้าใจว่าแปลว่ามีวิธีสร้างโค้ดโจมตีบันทึกไว้แล้ว และ ThaiCERT ก็เล่าว่า Drupal เตือนไว้ว่าเครื่องมือโจมตีอาจโผล่มาภายในไม่กี่ชั่วโมงหรือไม่กี่วันหลังเปิดเผย

ถ้าเว็บใช้บริการ Drupal Steward อยู่ ประกาศบอกว่ากันวิธีโจมตีที่รู้จักแล้ว แต่ก็ยังแนะนำให้อัปเดตโดยเร็ว เผื่อมีวิธีโจมตีแบบอื่นตามมา

วันเดียวกัน Drupal ออกอีกประกาศคือ SA-CORE-2026-018 (CVE-2026-132166) เป็นปัญหา gadget chain ระดับ Moderately critical คะแนน 14/25 ประกาศบอกว่าตัวมันเองใช้โจมตีตรง ๆ ไม่ได้ จะอันตรายก็ต่อเมื่อเว็บมีช่องโหว่อื่นที่ปล่อยให้ข้อมูลที่ไม่น่าเชื่อถือถูกแปลงกลับเป็นออบเจ็กต์ รุ่นที่โดนและรุ่นที่แก้ตรงกับข่าวนี้ อัปเดตครั้งเดียวก็จบทั้งสองตัวครับ

## ในไทยต้องทำอะไร

<div class="prose">

ThaiCERT ออกประกาศเตือนเมื่อ 20 พ.ย. 2569 (เลขที่ 642/69 กลุ่ม IT) ให้ตรวจรุ่นและอัปเดตโดยเร็ว ส่วนเว็บในไทยโดนจริงหรือยัง ผมยังไม่พบข้อมูลครับ

ขั้นตอนด้านล่างมาจากประกาศของ Drupal และหน้าคู่มือ "Securing the installer" ของ Drupal เอง

<ol class="news-steps">
<li class="is-key"><b>เช็กรุ่น Drupal ของทุกเว็บที่ดูแล</b>รวมถึงเว็บเก่า เว็บทดสอบ และเว็บที่จ้างคนอื่นทำไว้ ถ้ารุ่นยังต่ำกว่า 11.4.13, 11.3.22 หรือ 10.6.22 (ตามสายที่ใช้) แปลว่ายังไม่ปลอดภัย</li>
<li class="is-key"><b>อัปเดตเป็นรุ่นที่แก้แล้ว</b>สำรองไฟล์และฐานข้อมูลก่อน แล้วอัปเดตเป็น 11.4.13, 11.3.22 หรือ 10.6.22 ตามสายที่ใช้ ถ้าอยู่สายที่หมดอายุแล้ว ให้วางแผนย้ายขึ้นรุ่นที่ยังดูแลอยู่</li>
<li class="is-key"><b>ถ้ายังอัปเดตไม่ได้ ให้ล็อก install.php ที่ web server</b>Drupal แนะนำวิธีนี้ เพราะการตั้งค่ายังอยู่แม้อัปเดต core ไปแล้ว ใน Apache ใช้ <code>Location "/core/install.php"</code> กับ <code>Require all denied</code> ใน virtual host ใน Nginx ใช้ <code>location ^~ /core/install.php</code> ให้ตอบ 404 ต้องทำทุก virtual host ที่ให้บริการเว็บ รวมของ HTTPS ด้วย แล้วลอง <code>apachectl configtest</code> หรือ <code>nginx -t</code> ก่อนโหลดใหม่</li>
<li><b>ใช้ .htaccess แทน (เฉพาะ Apache)</b>ถ้าแก้ config ไม่ได้ ให้ใส่บล็อก <code>Files "install.php"</code> กับ <code>Require all denied</code> แต่ถ้าเว็บติดตั้งด้วย Composer ไฟล์ .htaccess จะถูกเขียนทับตอนอัปเดต ต้องเก็บส่วนนี้แยกไว้อีกไฟล์</li>
<li><b>หรือลบ core/install.php ออก</b>แต่ Composer จะเอาไฟล์กลับมาทุกครั้งที่ติดตั้งหรืออัปเดต หน้าคู่มือจึงแนะนำให้ใส่คำสั่งลบไว้ใน script ของ Composer ข้อเสียคือจะติดตั้งเว็บใหม่ผ่านเบราว์เซอร์ไม่ได้</li>
<li class="is-key"><b>ทดสอบว่าบล็อกได้จริง</b>ใช้ <code>curl -I</code> ยิงไปที่ <code>/core/install.php</code>, <code>/install.php</code> และ <code>/core/install.php/foo</code> ควรได้ 403 หรือ 404 ถ้าได้ 200 แปลว่ายังบล็อกไม่ได้</li>
<li><b>ตรวจสิทธิ์ settings.php</b>ตั้งให้เว็บเซิร์ฟเวอร์เขียนหรือเปลี่ยนสิทธิ์ไฟล์นี้ไม่ได้ ประกาศบอกว่าช่วยกันได้บางวิธีโจมตี แต่ไม่ได้กันทั้งหมด จึงใช้แทนการอัปเดตไม่ได้</li>
<li>สุดท้ายเช็กว่าเว็บยังทำงานปกติ และยังอัปเดตฐานข้อมูลผ่าน <code>drush updatedb</code> หรือ <code>/update.php</code> ได้ตามเดิม</li>
</ol>

ส่วนวิธีตรวจว่าเว็บโดนไปก่อนแล้วหรือยัง ประกาศของ Drupal ไม่ได้ให้ขั้นตอนไว้ครับ แต่ถ้าเว็บมีหน้าติดตั้งโผล่ขึ้นมา หรือค่าตั้งค่าเปลี่ยนไปโดยที่เราไม่ได้แก้เอง ให้ถือว่าผิดปกติและแจ้งทีมความปลอดภัย

</div>

</section>
